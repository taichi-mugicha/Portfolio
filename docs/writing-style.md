# 作品テキスト 文体ルール

作品原稿（`works/*.md`）の**書き方**のルール。
「どの項目を何字書くか」は [work-detail-text-format.md](work-detail-text-format.md) を参照。

作品テキストを書くとき・推敲するときは毎回これに沿って確認する。

## 1. 主語・視点

- ポートフォリオの作品紹介文である。「私（デザイナー）が何を考え、何を設計したか」が伝わる調子にする。
- 語尾は状態描写ではなく、**意思決定・行為を示す語尾**に統一する。
  - ✕ 状態描写：「〜なります」「〜あります」「〜います」
  - ○ 意思決定：「〜しました」「〜としました」「〜工夫しました」
  - 例：✕「後押しになっています」 → ○「後押しになるよう工夫しました」

## 2. 見出しと本文の呼応

- 見出しで使った印象的なキーワード・コピー（例：「困ってから」「もっと良く」）は、**本文中でも同じ言葉で回収する**。
  言い換え（例：「事後」「事前」）をして印象を薄めない。
- 見出しは「引き」の強さより**内容が一目でわかる具体性**を優先する。
- 見出し文の末尾に句読点（。など）はつけない。本文の文末は通常どおり句読点をつけてよい。

## 3. コンパクトさ

- 背景説明は最小限にし、**施策・工夫の部分に文字量を割く**。
- 同じ意味の内容が2文にまたがっていたら1文に統合する。
- 本質的に同じ主張の項目が複数あるなら、無理に分けず1本にまとめる。
  → POINT OF VIEW を1本に絞るのはこの原則による。

## 4. 助詞・接続の自然さ

- 動詞の対象が曖昧になる助詞を避ける。
  - ✕「〜に…デザインしました」 → ○「〜の」「〜向けに」など対象が明確な形
- 「〜たり」は**必ず対で使う**（片方だけの「たり」にしない）。
- 話が切り替わる系の接続詞（「しかし」「信頼性の面では」など）は飛躍を生むので避け、
  同じ流れの延長としてつながる接続（「さらに」など）を優先する。

## 5. 内容の配置・分類

- セクションの中身が、その見出しの性質と一致しているか確認する。性質が違うものは別セクションへ切り出す。
  - POINT OF VIEW＝思想・視点 ／ DESIGN＝具体的な機能・UIの工夫 ／ PROCESS＝制作の経緯
- **デザイナーが実際に寄与した範囲（UI・体験設計）と、企画側の仕様（機能そのものの有無）を混同しない。**
  見出し・本文の焦点は、あくまでデザイナーの工夫部分に当てる。
